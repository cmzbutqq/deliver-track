PROJECT PRESENTATION

电商物流配送可视化平台

一套基于地图服务的全栈物流管理系统
涵盖订单调度、轨迹模拟与实时追踪的可视化解决方案

React 18 NestJS PostgreSQL (PostGIS) 高德地图 API

产品设计与核心流程

02 / 11

本项目旨在构建一个连接“商家”与“用户”的物流信息平台，通过可视化的方式解决物流信息不透明的问题。

商家端 (Web)
  • 订单管理：处理订单状态流转（待发货 -> 运输中 -> 已签收）。
  • 发货调度：支持单点发货与批量发货，自动规划路径。
  • 数据看板：全盘监控运力分布与配送效率。
用户端 (H5)
  • 极简查询：无需登录，凭订单号直接查询。
  • 实时追踪：地图实时显示车辆位置与预计到达时间。

技术架构

03 / 11

系统采用前后端分离架构，重点在于处理地理信息数据（GIS）的存储与传输。

  • 前端 (React + Vite)：
    使用 Zustand 管理全局状态，集成 AMap (高德地图) 处理地图渲染与交互。
  • 后端 (NestJS)：
    模块化设计，负责业务逻辑与定时任务调度。
  • 数据库 (PostgreSQL + PostGIS)：
    利用 Prisma ORM 进行数据操作，使用 PostGIS 存储地理围栏（Polygon）等空间数据。
  • 通讯 (Socket.io)：
    后端向前端单向推送车辆实时坐标。

订单创建

左侧表单录入收件人信息与商品详情，右侧地图联动。输入地址后，系统自动进行地理编码（Geocoding），在地图上标记终点，所见即所得。

用户端核心页面。采用分屏布局：左侧（或移动端上方）为全屏地图，实时展示车辆移动；右侧为订单详情卡片与垂直时间轴，展示物流流转历史。

前端亮点：地图交互体验

06 / 11

在地图交互上，我们没有使用默认配置，而是针对业务场景进行了深度定制：

智能视野缩放 (Auto FitView)

在订单追踪页，系统会自动计算起点、终点和当前车辆位置的边界（Bounding Box），并调用地图 API 的 setFitView() 方法，确保所有关键要素始终自动适配在屏幕可见区域内，无需用户手动缩放。

配送区域可视化圈选

集成高德地图的 PolygonEditor 插件。商家可以在地图上通过鼠标点击、拖拽节点来绘制多边形配送区域。系统实时获取多边形的 GeoJSON 坐标数据并保存至数据库。

核心逻辑：后端运输模拟

07 / 11

为了演示完整的运输过程，后端内置了一套模拟引擎，用于生成和推送轨迹数据。

  • 路径获取：优先调用高德 Web API 获取真实的驾车导航路径点。如果 API 不可用，则自动降级为直线路径，在起终点间进行插值计算。
  • 时效控制：引入 SpeedFactor（速度系数）概念。根据不同的物流公司（如顺丰 vs 普快）设定不同的系数，使模拟的运输速度具有差异化。
  • 定时推送：后端定时任务按预定时间间隔读取路径点序列，并通过 Socket 逐个推送，模拟真实的车辆移动过程。

Path Generation Strategy

核心算法：多点配送调度

08 / 11

当商家选择“批量发货”时，系统不会简单地逐个发货，而是模拟了现实中的分仓配送逻辑。

1. 空间聚类 (Clustering)

系统遍历所有选中的订单，使用贪心策略将距离较近（例如 100km 半径内）的订单聚合为一个“配送簇”。这模拟了同一辆车负责临近区域的包裹。

2. 路径规划 (Routing)

在每个簇内部，使用最近邻算法规划路线。从起点出发，每次寻找离当前位置最近的下一个未送达点，形成一条串联所有订单的配送链，从而优化整体的配送顺序。

核心算法：配送区域判定

09 / 11

系统需要判断一个订单的收货地址是否位于商家设定的配送范围内。

射线法 (Ray Casting Algorithm)

我们将配送区域视为一个多边形，将收货地址视为一个点。算法从该点向任意方向发射一条射线，统计射线与多边形边界的交点数量。

  • 若交点数为奇数，则点在多边形内部。
  • 若交点数为偶数，则点在多边形外部。

通过此算法，我们在后端实现了对发货区域的有效校验，拦截不在配送范围内的违规订单。

数据价值与可视化

10 / 11

除了业务操作，平台还通过数据看板挖掘业务价值。

区域热力图

基于 PostGIS 聚合查询历史订单的经纬度数据，在地图上渲染热力图，直观展示订单高发区域，辅助商家进行库存前置或运力倾斜。

运力时效分析

统计不同物流公司在各区域的平均配送时长，以柱状图形式展现，帮助商家择优选择物流合作伙伴。
